# Strategy-selection bridge is a countermeasure-class map, not technique recommendations

The PRD title promises "→ strategy selection", but `zapret2-strategies` owns desync-technique choice, `zapret2-engine-reference` owns fooling-flag syntax, and VLESS transport engineering (mux/REALITY/XHTTP config) is out of scope. To avoid invading those zones with contradictory advice, the dpi-theory skill states the bridge as a *map from funnel layer to countermeasure class* only — it may name a class (uTLS-fingerprint, REALITY, mux/SNI-spread, statistical-morphing, fake-TTL) as a conceptual marker, but must never name a desync technique, give a fooling-flag value, or prescribe transport config. The boundary is enforced by an absence criterion: no Lua signature, no flag value, no transport-config parameter appears anywhere in the skill.
