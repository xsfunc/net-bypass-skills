# TTL split across two skills — detection vector vs flag mechanics

The `ip_autottl`/`ip_ttl` material has two faces: the *detection vector* (DPI fingerprints the OS by starting TTL and catches fake packets by TTL mismatch — Stage 0 of the funnel) and the *flag mechanics* (syntax, `delta,min-max` format, conntrack requirement). We split them: the detection vector lives in `dpi-tspu-strategy-theory/reference/ttl-detection.md`; the flag mechanics stay in `zapret2-engine-reference/reference/fooling.md` (already authored). The dpi-theory card bridges to the flag card by name without duplicating syntax. This corrects the PRD's source mapping (it named `VLESS/dpi-tls-june-2026.md` as the TTL source, but that file has zero TTL content — the real source is `DPI/dpi-analysis-pipeline.md` Stage 0) and respects the inter-skill boundary already established by the engine-reference pack.
