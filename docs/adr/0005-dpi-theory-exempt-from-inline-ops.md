# dpi-tspu-strategy-theory is exempt from the inline-ops rule

PRD #26/#29 require every skill to inline operational-safety procedures (safe-mode, rollback timer, preflight, validation, audit) marked `mirrors AGENTS.md §X as of <date>`, and to direct the agent to load `$openwrt-ops` before any router-facing step. `dpi-tspu-strategy-theory` is a theory skill with no router-facing steps, so there is nothing to mirror and no step to gate — a formal ops section would falsely signal that reading theory is a router-facing act. Instead a scope-marker in SKILL.md states the skill is theory-only and directs the agent to the ops-reminders of the three action-skills (`zapret2-strategies`/`zapret2-engine-reference`/`zapret2-router-deploy`) at the point of *acting* on the theory. Negative acceptance criteria: no `mirrors §X` markers, no `$openwrt-ops` directive.
